# Épico 8.10: MCP com OAuth e cadastro aberto (login com Google)

## Contexto
Hoje o MCP exige uma chave de API criada no painel, que só o admin acessa. Na prática, ninguém consegue instalar o MCP sozinho. Os outros apps do usuário (Assina, Minha Agenda, Contrata) usam OAuth: a pessoa cola a URL no Claude, clica em "Conectar", entra e pronto.

Decisões do usuário (22/11/2026):
- **Quem conecta:** qualquer um, com cadastro.
- **Login:** "Entrar com Google".
- **Freios:** limite diário de contas novas e limite de chamadas por conta.

Isso antecipa parte do roadmap 28.5 (perfis de cliente e limites de uso). A parte de preço e de planos continua fora.

O resultado: a pessoa cola `https://fechouporquanto.com.br/mcp` no Claude, entra com o Google, clica em "Permitir" e já usa as 5 ferramentas. A chave manual continua existindo para scripts.

Base: o desenho do Assina, que já está testado e passou pelo verifier.
- `assina/src/server/oauth/{server,authorize}.ts`
- `assina/src/app/oauth/{registrar,token,autorizar}`
- `assina/src/app/.well-known/*`
- `assina/src/server/auth/{google,oauth-state,allowlist}.ts`
- a migration `as_oauth`

Adapto esse desenho para o prefixo `m2_`, cito as regras do nosso spec e passo os limiares para `regras.ts`.

## Desenho
**Contas de cliente separadas do login do painel.**
- O cliente não usa o Supabase Auth. Por isso não há autocadastro nem SMTP no projeto compartilhado, e o `m2_perfis`, o `m2_eh_admin()` e o layout do painel ficam intactos.
- O admin continua entrando com e-mail e senha, e quem não é admin continua barrado no painel.

**Login com Google (adaptado de `assina/src/server/auth/google.ts`)**
- Escopos `openid email`, com PKCE e state guardados num cookie curto.
- O `id_token` é validado com `jose`: assinatura, aud, iss, exp e `email_verified`.
- A sessão do cliente é um cookie HttpOnly assinado com HMAC (`SESSION_SECRET`). Ele vale só para as telas do fluxo OAuth.

**OAuth 2.1 (spec MCP, RFCs 8414, 9728, 7591, 7636 e 9700)**
- **Metadados:**
  - `GET /.well-known/oauth-protected-resource[/mcp]` informa que o recurso é `${SITE}/mcp` e que o servidor de autorização é `${SITE}`;
  - `GET /.well-known/oauth-authorization-server` lista os endpoints, `S256`, `none` e `authorization_code`.
- **`POST /oauth/registrar`:** registro público de cliente (RFC 7591).
  - O `redirect_uri` tem de ser https, ou http em localhost/127.0.0.1.
  - Há limite de URIs e de tamanho do nome.
- **`GET /oauth/autorizar`:** a tela de consentimento.
  - Valida os parâmetros e mostra erro sem redirecionar, para não virar redirecionador aberto.
  - Sem sessão, manda para "Entrar com Google" e volta.
  - Mostra o nome do cliente, o host de volta, o que ele pode fazer (ler as 5 ferramentas) e o que não pode (escrever, ver dados de pessoas). Tem os botões Permitir e Cancelar.
- **`POST /oauth/autorizar/decidir`:** confere tudo de novo e grava um código válido por 10 min, guardado só como hash.
- **`POST /oauth/token`:** troca o código pelo token `fpq_mcp_…`.
  - A troca é atômica.
  - Código reusado revoga o token que ele gerou.
  - Sem `expires_in` e sem refresh token. O token vale até ser revogado.
- **`/api/mcp` aceita dois tipos de credencial:**
  - a chave do painel (`m2_chaves_api`, como hoje);
  - o token OAuth (`m2_tokens_mcp`).
  - O 401 passa a mandar `WWW-Authenticate: Bearer resource_metadata="${SITE}/.well-known/oauth-protected-resource"`. É esse cabeçalho que faz o Claude abrir o fluxo sozinho.
- **Proxy:** o matcher passa a excluir também `.well-known`, `oauth/` e `api/auth/google`.
- **Endereços:** vêm sempre de `NEXT_PUBLIC_SITE_URL`, nunca do Host da requisição.

**Freios (limiares em `regras.ts`, com o número da regra nova)**
- **Contas novas:** no máximo `CLIENTES_NOVOS_POR_DIA` (50) nas últimas 24 h. Acima disso, a tela mostra a mensagem da seção 15.
- **Chamadas por conta:** `MCP_CHAMADAS_POR_MINUTO` (30) e `MCP_CHAMADAS_POR_DIA` (1.000), contadas na função atômica `m2_registra_uso_mcp`. Acima disso:
  - a resposta é o erro de ferramenta da seção 15: "Limite de uso atingido…";
  - o status é 429, com `Retry-After`.
- **Chaves do painel:** não entram nesse limite, porque são do admin.
- **Bloqueio:** o admin bloqueia uma conta no painel, e os tokens dela param na hora.

## Banco (migration nova, RLS só para admin, escrita só pelas funções de serviço)
- **`m2_clientes`:** `id`, `google_sub` (unique), `email`, `criado_em`, `bloqueado_em`. Não guardo o nome.
- **`m2_oauth_clientes`:** `id`, `nome`, `redirect_uris text[]`, `criado_em`.
- **`m2_oauth_codigos`:** `codigo_hash` (pk), `oauth_cliente_id`, `cliente_id`, `redirect_uri`, `code_challenge`, `expira_em`, `usado_em`, `token_id`.
- **`m2_tokens_mcp`:** `id`, `cliente_id`, `oauth_cliente_id`, `prefixo`, `hash_token` (unique), `revogado_em`, `ultimo_uso_em`, `criado_em`.
- **`m2_uso_mcp`:** `token_id`, `janela` (minuto) e `chamadas`, com pk (`token_id`, `janela`). As linhas com mais de 2 dias são apagadas pela própria função.
- **Funções (SECURITY DEFINER, só service_role):**
  - `m2_cria_cliente(sub, email, limite_dia)`: é um upsert e devolve null quando o limite estoura;
  - `m2_cria_codigo_oauth(…)`;
  - `m2_troca_codigo_oauth(…)`;
  - `m2_registra_uso_mcp(token_id, por_minuto, por_dia)`: devolve se pode e quantos segundos esperar.
- **Leitura pelo admin no painel:** `m2_clientes_mcp()`, com e-mail, criado em, último uso, chamadas hoje e tokens ativos.
