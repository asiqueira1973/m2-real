Referência: spec.md seção 8.0, 18.1–18.5, 22.1 e Anexo B. Plano mestre: `plans/00-plano-mestre.md`.

## Objetivo
Deixar o repositório pronto e com os guardrails do Anexo B ativos antes de qualquer feature.

## Tarefas e arquivos
1. **Git**: `git init` (`main`), `.gitignore` (planilhas da raiz, `.env*` exceto `.env.example`, `supabase/.temp`, `.claude/fix-mode`). Branch `epico/8-0-guardrails`.
2. **Anexo B, copiado literalmente do spec**:
   - `.claude/settings.json`
   - `.claude/hooks/guard-secrets.sh`, `guard-migrations.sh`, `guard-tests.sh`, `guard-coleta.sh`, `remind-advisors.sh` (todos com `chmod +x`)
   - `.claude/agents/verifier.md`
   - `REVIEW.md`
3. **Monorepo (seção 18.3)** com npm workspaces:
   - `package.json` na raiz com os scripts `typecheck`, `test`, `build`, `db:test` e `ingestao`
   - `tsconfig.base.json` (strict)
   - `apps/web`: Next.js (App Router) + Tailwind, com uma página mínima. Pastas `src/app/(painel)`, `src/app/api`, `src/server` e `src/features` já criadas.
   - `packages/ingestao`: `src/cli.ts` (despacha as rotinas da 4.4 e, por ora, só valida o nome), `src/config/regras.ts` (vazio, com cabeçalho), pastas `itbi/ iptu/ anuncios/ leiloes/ calibracao/ bairros/ shared/` e Vitest com um teste do `cli`.
   - `packages/db`: `src/index.ts` e `src/types.ts` (este último é placeholder; os tipos são gerados no 8.1).
   - `supabase/` via `supabase init`; `supabase/migrations/`, `supabase/seed/` e `supabase/tests/` vazios. O `db:test` roda `supabase test db`.
4. **Documentos**: `CLAUDE.md` (uma página: convenções, mapa, comandos, pegadinhas, regra de ouro), `README.md` (setup) e `.env.example` (variáveis da 18.4).

## Teste dos hooks (critério 3)
Cada hook é provocado uma vez, com a saída colada no chat e registrada no fim deste arquivo:
- `guard-secrets`: Write em `apps/web/src/features/teste/a.ts` com `SUPABASE_SERVICE_ROLE_KEY`, e componente `'use client'` importando `@/server/...`.
- `guard-migrations`: JSON com um caminho de migration já versionada num repositório git temporário no scratchpad (`CLAUDE_PROJECT_DIR` apontado para ele), sem sujar o repositório real.
- `guard-tests`: `touch .claude/fix-mode` → Edit de um `*.test.ts` → bloqueio → `rm .claude/fix-mode`.
- `guard-coleta`: Write em `packages/ingestao/src/anuncios/teste.ts` com `telefone`, e outro com `writeFile`.
- `remind-advisors`: Write em `supabase/migrations/…` → aviso.
- Cada um é provocado por pipe de JSON (saída e exit code) e, nos que dá, também ao vivo pela ferramenta.

## Pegadinha registrada
O `guard-coleta` bloqueia termos como cpf, devedor e proprietario em qualquer arquivo não-teste de `anuncios/` e `leiloes/`. Por isso os filtros de campos são allowlists positivas, e os prompts de extração evitam esses termos.
